# YeMind 文档分类与时间命名实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 `docs/` 整理为稳定规范、当前设计与计划、版本证据、回归记录和 v0.9 归档，并让所有历史阅读型文档名称包含精确到分钟的北京时间。

**Architecture:** 先用只读清单生成器根据 Git 首次提交时间建立旧路径到新路径映射，再由迁移脚本执行 Git 感知移动和引用替换。稳定规范维持固定路径，历史文档按类别归档；最后通过 Vitest 与独立检查脚本验证命名、映射和本地链接。

**Tech Stack:** Node.js ESM、PowerShell、Git、Vitest、Markdown

---

## 文件职责

- `scripts/docs/documentNaming.mjs`：分类、时间推导、目标文件名和路径校验的纯函数。
- `scripts/docs/generateDocumentMigration.mjs`：扫描旧文档并生成迁移清单。
- `scripts/docs/applyDocumentMigration.mjs`：根据清单移动文件并更新仓库内路径引用。
- `scripts/docs/checkDocumentation.mjs`：检查历史命名、稳定路径、迁移结果和 Markdown 本地链接。
- `tests/suites/diagnostics-release/documentStructure.suite.ts`：覆盖分类、时间和链接检查规则。
- `docs/document-migration-map.json`：完整审计映射。
- `docs/README.md`：当前文档总入口。
- `docs/standards/`：长期稳定规范。
- `docs/designs/`、`docs/plans/`：时间化设计与计划。
- `docs/releases/vX.Y.Z/`：正式版本测试、验证和验收证据。
- `docs/archive/v0.9/`：v0.9 设计、边界、矩阵、验证和构建清单。

- [ ] **Step 3：实现生成器**

生成器需要：

1. 使用 `git log --diff-filter=A --follow --format=%aI -- <path>` 获取首次进入 Git 的时间。
2. 未跟踪文件使用 `birthtime`，不可用时使用 `mtime`。
3. 转为 `Asia/Shanghai` 的 `YYYY-MM-DD-HHmm`。
4. 输出包含 `oldPath`、`newPath`、`timestamp`、`timeSource`、`category` 的稳定排序 JSON。
5. 检测目标路径冲突并以非零退出码中止，不生成 `(1)` 后缀。

- [ ] **Step 3：实现迁移执行器**

执行器必须：

1. 解析并验证 `docs/document-migration-map.json`。
2. 确认所有旧路径位于仓库 `docs/` 内，所有目标也位于 `docs/` 内。

6. 不修改哈希、测试数量、验收结论和历史日期。
7. 支持 `--dry-run`，默认不写入。
