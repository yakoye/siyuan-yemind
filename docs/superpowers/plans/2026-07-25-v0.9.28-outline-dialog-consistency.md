# YeMind v0.9.28 Outline and Dialog Consistency Implementation Plan

## Goal

Resolve the remaining outline accessory alignment, image-preview arbitration, clipart direct-manipulation, anchored-dialog edge placement and inconsistent dialog chrome reported after v0.9.27.

## User-visible requirements

1. Outline marker icons use a correctly scaled sprite viewport without an offset wrapper.
2. Outline notes and comments use their native YeMind icons; comments no longer display a leading count badge.
3. Hover previews stabilize immediately and reposition after content size changes.
4. Outline image double-click always opens the shared map lightbox; single-click still opens editing.
5. Canvas clipart keeps the eight resize handles and top-right delete control while a single click opens the clipart picker.
6. Marker and clipart pickers choose among eight anchored placements, remain inside the viewport and avoid their source asset whenever possible.
7. Every YeMind dialog shares one title height, bold title, aligned close button and right-aligned footer actions.

## TDD sequence

- Add v0.9.28 unit/offline contracts and browser smoke assertions against v0.9.27.
- Confirm the new contracts fail.
- Implement compact marker background geometry and semantic status icons.
- Add two-pass/resize-observed hover preview placement and longer single/double click arbitration.
- Restore clipart selection geometry and add eight-direction dialog placement.
- Add shared dialog chrome helper and apply it to every Dialog constructor.
- Build, run offline and browser regressions, package deterministically, re-extract and repeat validation.
