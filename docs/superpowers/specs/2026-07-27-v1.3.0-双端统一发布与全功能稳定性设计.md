# YeMind v1.3.0 双端统一发布与全功能稳定性设计

## 1. 目标

YeMind v1.3.0 建立“一套核心源码、两个宿主入口、一个版本号、一次发布产生两个成品”的长期维护方式，并完成思源插件版和独立网页版的全功能回归、明暗主题、工具栏显隐、图标语义和交互稳定性整理。

本版本交付后必须满足：

1. 导图、大纲、导入导出、主题、样式和节点内容能力只维护一套核心实现。
2. 思源插件版与独立网页版使用相同的编辑器、模型、命令、导入导出和样式代码。
3. 一个版本命令同步所有版本标记。
4. 一个发布命令同时生成思源插件 ZIP、独立网页版 ZIP、校验和与发布清单。
5. Git Tag 触发完整验证、GitHub Release 和 GitHub Pages 部署。
6. 浅色、深色和跟随宿主/系统三种界面外观下，全部主要功能清晰可用。
7. 导图和大纲的增删改查、拖动、资源、富文本、折叠和结构转换完成自动化与人工验收。
8. 不迁移、不覆盖、不删除用户导图、设置、检查点和复习数据。

## 2. 本版本范围

### 2.1 包含

- 双端共享架构边界固化。
- 统一版本、构建、打包、校验和与发布流程。
- GitHub Release 双 ZIP 产物。
- GitHub Pages 同版本部署。
- 应用级浅色、深色、跟随系统/思源三态外观。
- 顶部、左侧、底部工具栏的统一固定和分侧自动隐藏。
- 三侧工具栏隐藏后的可发现边缘把手。
- 大纲行六点拖动把手默认隐藏，鼠标接近、行悬停、键盘聚焦或拖动时显示。
- 工具栏和主要菜单图标语义、状态与无障碍属性整理。
- 用户列出的导图、大纲和通用能力全量验证；发现缺陷时以回归测试先行修复。
- 双端桌面、窄屏、浅色、深色的浏览器验收。

### 2.2 不包含

- “复习与卡片”数据模型、卡组、复习算法和复习视图。
- FSRS、Anki 导出和全局复习队列。
- 大规模重写 simple-mind-map 引擎。
- 与本版本稳定性目标无关的全新布局、主题或内容类型。

“复习与卡片”作为下一独立功能版本设计。现有模糊/挖空能力保持兼容，本版本只验证其在明暗主题和导图/大纲中的可用性。

## 3. 共享架构

### 3.1 核心代码

以下目录是思源插件版和独立网页版的唯一业务实现：

- `src/core/`：导图引擎扩展、布局、拖动和外观事务。
- `src/editor/`：共享编辑器、导图/大纲/分屏、工具栏和面板。
- `src/model/`：导图、设置、检查点等领域模型。
- `src/content/`：待办、备注、批注等节点内容状态。
- `src/transfer/`：共享导入导出。
- `src/ui/`：共享菜单、弹窗、资源和内容交互。
- `src/styles/`：共享编辑器视觉系统。

不得在 `web/` 复制这些能力。修复共享功能时必须优先修改 `src/`，并在两个宿主中验证。

### 3.2 宿主边界

思源插件端只负责：

- 插件启动与卸载。
- 思源标签页、停靠栏、消息和宿主 API。
- 思源存储适配。
- 思源外观状态桥接。

独立网页端只负责：

- 网页启动入口与导图库侧栏。
- IndexedDB 存储适配。
- 浏览器消息、弹窗和菜单适配。
- 浏览器系统外观桥接。

共享编辑器通过明确的宿主接口使用消息、确认、外部链接、文件选择和持久化服务，不直接复制宿主判断分支。

## 4. 版本、构建与发布

### 4.1 版本

`package.json` 是唯一版本源。版本更新脚本将同步：

- `package.json`
- `package-lock.json`
- `plugin.json`
- `VERSION`
- `web/VERSION`
- `src/plugin/constants.ts`
- `src/releaseInfo.ts`
- 发布文档中的当前版本标记

`npm run check:version` 继续作为只读门禁，不自动掩盖版本不一致。

### 4.2 发布产物

`npm run release:build` 必须先验证再生成：

- `release/siyuan-yemind-v1.3.0.zip`
- `release/yemind-web-v1.3.0.zip`
- `release/release-manifest-v1.3.0.json`
- `release/SHA256SUMS.txt`

思源插件 ZIP 根目录直接包含 `plugin.json`、`index.js`、`index.css`、`assets/`、`i18n/`、图标、许可证、说明和版本文件，不能多套一层目录。

网页版 ZIP 根目录直接包含 `index.html`、构建资源、`assets/`、图标、`.nojekyll` 和版本文件，解压后可部署到任意静态服务器。

两个 ZIP 都不得包含：

- `data/`
- 用户导图
- 设置
- 检查点
- 诊断记录
- `node_modules/`
- 源码映射
- 临时测试目录

### 4.3 GitHub

推送 `v1.3.0` Tag 后，发布工作流依次执行：

1. `npm ci`
2. 版本一致性检查
3. 类型和语法检查
4. 主工程测试
5. 网页版测试
6. 离线回归与资源完整性检查
7. 插件生产构建
8. 网页生产构建
9. 发布包生成和内容审计
10. 上传两个 ZIP、发布清单和 SHA-256
11. 创建 GitHub Release
12. 将同一份 `web-dist/` 部署到 GitHub Pages

任意步骤失败均不得创建完整 Release 或更新 Pages。

## 5. 明暗主题

### 5.1 外观设置

新增应用级 `appearanceMode`：

- `system`：思源端跟随思源，网页端跟随操作系统。
- `light`：强制浅色。
- `dark`：强制深色。

该设置写入应用设置，不写入单张导图。导图主题仍表示节点和连线配色，界面“外观”不得与导图“主题”混用名称。

### 5.2 切换范围

切换外观时必须同步更新：

- 网页导图库侧栏。
- 导图画布背景和节点主题变体。
- 顶部、左侧、底部工具栏。
- 导图、大纲和分屏。
- 右键菜单及子菜单。
- 设置、结构、主题、线型、样式和导出面板。
- 节点样式、关联线、外框、搜索和富文本工具栏。
- 图片预览、备注、批注、待办、代码、公式和颜色控件。
- 空状态、错误消息、禁用状态、选中状态和键盘焦点。

### 5.3 对比度

普通文字、主要图标和输入内容以 WCAG AA 4.5:1 为目标；大号文字和非文本控件边界以 3:1 为目标。不能只用颜色区分只读、选中、危险、禁用或复习遮挡状态。

## 6. 工具栏显隐

### 6.1 状态模型

保留一个应用级全局状态：

- `pinned`：三侧工具栏固定显示。
- `auto`：三侧工具栏分别自动隐藏。

不提供三条工具栏各自固定的八种组合，降低理解和维护成本。

自动隐藏模式下，每条工具栏独立维护：

- `visible`
- `hideTimer`
- `interactionOwner`
- `focused`
- `panelOpen`

移动到顶部边缘只显示顶部工具栏；移动到左侧只显示左侧工具栏；移动到底部只显示底部工具栏。任何一条显示或隐藏不得强制改变另外两条。

### 6.2 边缘把手

工具栏隐藏后，对应边缘保留半胶囊把手：

- 顶部把手位于顶部中间。
- 左侧把手位于左侧中间。
- 底部把手位于底部中间。
- 把手带方向箭头和准确 `aria-label`。
- 鼠标进入、点击、键盘聚焦、Enter、Space 和触屏点击均可展开。
- 工具栏出现后把手暂时隐藏。
- 触屏点击展开后，执行操作或点击画布才收起，不依赖 hover。
- 打开该工具栏所属面板、菜单或输入控件时保持显示。
- 禅模式隐藏三条工具栏及三个把手，只显示现有退出禅模式入口。

动画只使用 `opacity` 和 `transform`，时长 120–180ms，不触发布局重排。

### 6.3 大纲六点拖动把手

大纲每行的六点拖动把手采用 Codex 任务列表式渐进显示：

- 默认不可见但保留稳定命中区，不造成文本横向跳动。
- 鼠标进入行左侧把手热区、整行悬停、键盘聚焦该行或开始拖动时显示。
- 离开行且没有焦点、菜单或拖动状态后淡出。
- 拖动过程中始终显示。
- 触屏设备在首次点按行后显示，第二次从把手开始拖动。
- 把手不能遮挡折叠三角、标号、图片或正文。
- 大纲整体不为永久把手保留明显空白栏。

## 7. 图标与操作语义

### 7.1 工具栏职责

- 顶部：导图/分屏/大纲、搜索、结构、导图主题、线型、整图样式、导入、导出和保存状态。
- 左侧：检查点、撤销、重做等编辑历史动作。
- 底部：标题、统计、适配视图、画布模式、只读、禅模式、工具栏显隐、界面外观、缩放、全屏和帮助。

### 7.2 调整规则

- YeMind 品牌不再执行“适配视图”。
- “适配视图”只保留在底部。
- `＋`、`−`、`?` 替换为统一 SVG。
- 导入、导出使用图标加文字。
- “界面外观”使用系统/太阳/月亮图标，不能叫“主题”。
- 状态按钮统一显示当前状态，提示文字说明点击后的动作。
- 图钉提示明确为“固定全部工具栏”或“启用工具栏自动隐藏”。
- 图标统一使用 `currentColor`、尺寸、线宽、命中区和焦点环。
- 每个无文字图标必须有 `title` 和 `aria-label`。
- 删除等危险动作保留文字和危险色，不使用只有图标的不可逆入口。

## 8. 数据与兼容

- 现有 `toolbarsPinned: boolean` 自动迁移为新的工具栏模式，`true → pinned`，`false → auto`。
- 没有 `appearanceMode` 的设置默认为 `system`。
- 导图文档结构不因界面外观和工具栏调整而改变。
- 现有模糊/挖空、备注、批注、待办、标签、图片、剪贴图、标号、外框和关联线数据保持不变。
- 布局转换不得丢失节点 UID、内容、资源、扩展状态、关联线、外框、展开状态和自定义样式。
- 导入导出继续兼容 v1.2.0 及旧版格式。

## 11. 错误处理与诊断

- 用户输入或文件错误显示中文可行动消息。
- 导入、迁移和存储更新使用事务或失败回滚。
- 主题、工具栏和图片加载失败不得导致编辑器不可用。
- 浏览器控制台不得留下预期内但未处理的错误。
- 诊断报告记录版本、宿主、外观、工具栏模式、当前布局和最后失败步骤，不记录导图正文。
- 发布工作流失败时保留构建日志和测试报告，不上传部分正式产物。

## 12. 开发与验收流程

1. 设计文档：记录目标、边界、架构、数据、交互、测试和验收。
2. 实施计划：把设计拆成测试先行的小任务，列出精确文件和命令。
3. 开发测试用例：每个新增行为和发现的缺陷先建立失败测试。
4. 开发实现：最小实现通过测试后再整理代码。
5. 局部验证：每个任务运行对应测试。
6. 全量验证：类型、语法、主测试、网页测试、离线测试、资源、插件构建、网页构建、发布包审计。
7. 浏览器验收：执行第 9 节矩阵中的双端场景并保存证据。
8. 思源运行目录验收：同步后校验版本、清单和哈希。
9. 发布验收：生成双 ZIP、校验和和清单，解压检查目录结构。
10. Git 验收：工作树干净，提交和远端一致。
11. GitHub 验收：Tag、Release 资产和 Pages 工作流成功。
12. 最终报告：列出通过项、跳过项、已知限制、提交号、Tag、Release 和 Pages 地址。
