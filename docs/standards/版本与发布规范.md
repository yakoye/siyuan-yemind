# YeMind 版本与发布规范

## 1. 目标

YeMind 只维护一套 TypeScript 源码，同时产出思源插件和独立网页版。版本号、测试门禁、发布清单与线上部署必须来自同一个已验证提交，不允许手工拼装 ZIP 或分别修改两端代码。

## 2. 版本契约

版本使用 `Major.Minor.Patch`。以下 8 个标记必须一致：

- `package.json`
- `package-lock.json` 根版本
- `package-lock.json` 根包版本
- `plugin.json`
- `VERSION`
- `web/VERSION`
- `src/plugin/constants.ts` 的 `PLUGIN_VERSION`
- `src/releaseInfo.ts` 的 `buildId`

设置版本：

```text
npm run version:set -- 1.5.1
npm run check:version
```

版本修改后必须同步更新 `CHANGELOG.md`、中英文 README、网页版 README 和本版本验收记录。

## 3. 共享边界

- `src/`、`vendor/simple-mind-map-runtime/`、`assets/` 与 `i18n/` 是双端共享实现和固定资源。
- `src/plugin/` 负责思源宿主适配；`src/web/` 负责浏览器存储和网页版宿主适配。
- 导图数据、结构布局、富文本、附件、关联线、导入导出、主题和交互控制器不得复制成两套实现。
- 思源私有 API 必须停留在适配层，网页版不得依赖 `/plugins/`、思源 SVG sprite 或宿主全局变量。

## 4. 发布门禁

发布前按顺序执行：

```text
npm ci
npm run check:version
npm run test:structure
npm run test:syntax
npm run check
npm test
npm run test:web
npm run test:offline
npm run verify:assets
npm run test:e2e
npm run release:build
npm run release:verify
```

任何核心测试失败、版本漂移、发布包缺文件、哈希不一致、运行目录数据被删除或 Pages 冒烟失败都阻断发布。测试矩阵见 `docs/standards/测试与验收.md`。

## 5. 发布产物

`npm run release:build` 先构建两端，然后写入 `release/v<version>/`：

- `siyuan-yemind-v<version>.zip`：仅包含思源可安装运行白名单。
- `yemind-web-v<version>.zip`：可部署到任意静态站点的 `web-dist/`。
- `release-manifest.json`：记录版本、提交、构建时间、文件大小和 SHA-256。
- `SHA256SUMS`：记录两个 ZIP 和清单自身的 SHA-256。

`npm run release:verify` 会重新计算哈希、检查字节数并打开两个 ZIP 验证必要文件。输出目录限定为仓库根目录的 `release/v<version>`，脚本拒绝清理其他路径。

## 6. GitHub 自动化

- `ci.yml`：对 `main` 提交和拉取请求执行版本、结构、语法、类型、单元、网页、双端构建与桌面/移动浏览器测试。
- `pages.yml`：只在主分支验证成功的构建流程中上传 `web-dist/`，再部署 GitHub Pages。
- `release.yml`：只响应 `v*` 标签；标签版本必须等于项目版本，随后构建、校验并发布四个产物。

标准发布流程：

1. 在分支完成开发、文档和本地全量验收。
2. 将已验证提交合并到 `main` 并等待 CI、Pages 成功。
3. 创建与项目版本一致的标签，例如 `v1.5.1`。
4. 等待 Release 工作流成功，核对下载文件和 `SHA256SUMS`。
5. 对 GitHub Pages 执行首页、建图、保存、导入导出和移动视口冒烟。

## 7. 运行目录与数据

`npm run sync:runtime` 只允许目标：

```text
D:\myDatabase\SiYuan\data\plugins\siyuan-yemind
```

同步白名单为插件根文件、`assets/` 和 `i18n/`，已有 `data/` 必须保留。若思源占用文件导致原子目录替换失败，可使用 `npm run sync:runtime:in-place`；目标校验、白名单清理与 `data/` 保留规则不变。

## 8. 回滚

- 插件回滚：下载上一稳定 Release 的插件 ZIP，覆盖运行白名单，保留 `data/`。
- 网页回滚：重新部署上一稳定标签生成的网页版 ZIP。
- GitHub Release 或 Pages 出现问题时停止新增标签，保留失败 Actions 日志和浏览器 trace。
- 不删除或改写用户导图数据来解决代码发布问题。
