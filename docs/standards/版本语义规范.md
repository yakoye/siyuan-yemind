# YeMind 语义化版本规则

YeMind 正式版使用 `Major.Minor.Patch`。需要用户实机确认的修复先使用
`Major.Minor.NextPatch-rc.YYYYMMDD.HHmm` 候选号；候选构建不占用正式版本号，不打正式标签，
确认通过后才发布对应的 `Major.Minor.NextPatch`。

当前发布版本：`1.6.0`。

Codex 在发布时按本规则自主决定版本号、Git 标签和 GitHub Release，无需逐次询问用户。用户明确指定版本时，以用户要求为准。

## Major

出现不兼容的数据格式、公共行为或迁移要求时增加主版本，并在发布说明中给出迁移与回滚办法。

## Minor

兼容前提下增加完整功能、设置分区或重构主要子系统时增加次版本并将 Patch 归零。例如 v0.7.0 新增“关于”、版本门禁并升级诊断子系统。

## Patch

单一缺陷、小范围交互、文案或样式修复，且不改变数据格式和主要架构时增加修订号。

## 自主判定与记录

- Patch：兼容性缺陷修复、小范围视觉或交互整理。
- Minor：兼容的新能力、成组功能交付或主要子系统重构。
- Major：不兼容的数据、接口、持久化或使用方式变化，需要迁移说明。
- 每次发版必须在 `CHANGELOG.md` 和本版本验收记录中写明选择该版本级别的理由。
- 不为了“看起来更新很多”跳级；也不把明显的新能力长期堆在 Patch 中。

## 发布身份门禁

每次发布必须统一：

- `package.json`
- `package-lock.json`
- `plugin.json`
- `src/plugin/constants.ts`
- `src/releaseInfo.ts`
- 设置 → 关于
- 诊断报告与版本一致性文件
- README / CHANGELOG / 本版本验收记录
- 发布 ZIP 文件名
- 验证报告

任何一项不一致都不得发布。

仓库根目录的 `VERSION` 是插件发布标记，`web/VERSION` 是独立网页版发布标记。二者必须与 `package.json`、`package-lock.json`、`plugin.json`、`src/plugin/constants.ts` 和 `src/releaseInfo.ts` 完全一致；提交前执行 `npm run check:version`。
