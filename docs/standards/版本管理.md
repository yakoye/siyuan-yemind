# 版本管理

YeMind 使用语义化版本。当前版本以根目录 `VERSION` 为唯一机器可读入口，不在本文硬编码容易过期的版本号。

## 版本号位置

发布时以下位置必须完全一致：

- `package.json`
- `package-lock.json` 根版本和根包版本
- `plugin.json`
- 根目录 `VERSION`
- `web/VERSION`
- `src/plugin/constants.ts` 中的 `PLUGIN_VERSION`
- `src/releaseInfo.ts` 中的 `buildId`

升级版本与检查：

```text
npm run version:set -- 1.6.0
npm run check:version
```

任何一处不一致都会失败。插件构建、网页版构建和 GitHub Pages 工作流都会执行该检查。

## 递增规则

- 修复错误且保持兼容：增加补丁版本，例如 `1.0.0` → `1.0.1`。
- 新增兼容功能：增加次版本，例如 `1.0.1` → `1.1.0`。
- 出现不兼容的数据、接口或使用方式变化：增加主版本，例如 `1.x` → `2.0.0`。
- 每次发布同步更新 `CHANGELOG.md`、中英文 README 和验证记录。
- 未经用户实机确认的修复必须使用 `X.Y.Z-rc.N`；失败只递增同一目标的 `rc.N`。
- Codex 自主选择目标版本、开发、测试、构建并发布 RC，无需逐次询问；选择理由必须进入本版本验收记录。
- 用户确认对应 RC 已解决原问题后，才允许去掉候选后缀并发布稳定标签和正式 Release。

双端发布命令、产物名称、CI 门禁和回滚要求见 `docs/standards/版本与发布规范.md`。
