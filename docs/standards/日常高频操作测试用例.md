# YeMind 日常高频操作测试用例

> 文档类型：长期有效测试规范  
> 适用端：独立网页版、思源插件版  
> 正式基线：`docs/standards/回归验收清单.md`  
> 重点范围：新建、编辑、选择、复制、剪切、粘贴、删除、拖动、折叠、格式、撤销重做、保存重开  
> 原则：每个用户报告的问题都必须成为永久回归用例；旧版本通过记录不能代替当前候选提交的实际执行证据。

## 1. 测试目标与结论边界

本用例集用于把日常最高频操作做成稳定、可重复、可阻断发布的验收矩阵，重点防止以下近期问题再次出现：

- 新建节点后首帧空白，默认文字稍后才出现。
- 编辑器、SVG 文字、节点边框出现双层、闪白、重影、错位或跳动。
- 从节点 A 切换到节点 B 时，旧工具栏、旧选区或旧动画帧污染新节点。
- Delete、Backspace、Ctrl+X 不能一次删除真实选区，或误删整个节点。
- 复制文字、图片、剪贴图和节点时对象判断错误，旧选区或多选节点抢占当前操作。
- 同文件与跨文件粘贴时结构、语义格式、资源、UID 或整节点视觉样式处理错误。
- 宽度拖动、画布平移、缩放和宿主滚动时出现闪白、控件漂移或坐标不同步。
- 导图与大纲对同一棵树的编辑、选择、拖动、折叠和剪贴板行为不一致。
- 撤销重做只恢复部分状态，或保存、重开后丢失文字、资源、尺寸、结构。

软件测试不能证明“绝对零缺陷”。本规范把“可以交付”定义为：全部适用阻断用例通过、无新增跳过、无未解释控制台错误、双端实机结果一致、发布证据完整。任何一项缺失都不能表述为“一点问题都没有”。

每轮测试新建独立工作区，禁止直接使用唯一一份真实用户数据。

| `YM-DATA-02` | 3 层、每层 3 个节点，含左右分支和折叠分支 | 拖动、折叠、多选、结构复制 |
| `YM-DATA-03` | 中英文、emoji、标点、链接、公式、代码块、三行以上长文本 | 选区、格式、换行、编辑几何 |

| `YM-DATA-05A/B` | 同时打开的两个独立文件，使用不同主题和节点样式 | 跨文件复制、状态隔离 |

执行前记录：

- 候选提交 SHA、版本号、构建时间、浏览器版本、思源版本和操作系统。

- 控制台已有错误与警告；测试期间新增项必须单独判定。

## 3. 测试方法和手段

### 3.1 分层方法

| 层级 | 方法 | 主要验证内容 | 工具与证据 |
|---|---|---|---|
| L1 纯逻辑 | 等价类、边界值、决策表、状态转换 | 复制优先级、UID 规则、结构载荷、命令守卫 | Vitest；失败/通过日志 |
| L2 组件集成 | DOM 事件、焦点、选区、渲染事务 | Quill、结构化大纲、右键菜单、图片控件、历史栈 | Vitest + jsdom；DOM 快照 |
| L3 浏览器 E2E | 只使用公开 UI 的真实键鼠操作 | 高频完整流程、跨文件、逐帧几何、IndexedDB | Playwright；trace、截图、视频、控制台日志 |
| L4 思源实机 | 冷启动、WebView2、宿主滚动与焦点抢占 | 插件加载、宿主快捷键冲突、真实保存、运行目录一致性 | 思源 3.7.3；录屏、截图、运行日志、文件哈希 |
| L5 外部互操作 | 在 YeMind 与第三方应用间复制粘贴 | 图片二进制、HTML、纯文本降级 | 画图/图片编辑器、记事本或富文本编辑器；结果截图 |
| L6 发布验证 | 解包重装、版本与哈希校验 | 发布包未混入用户数据，产物与候选提交一致 | `release:build`、`release:verify`、SHA-256 |

### 3.2 专项手段

- **决策表**：来源表面为导图/大纲，状态为编辑/非编辑，载荷为文字/图片/节点，目标为导图/大纲，文件关系为同文件/跨文件。
- **状态转换**：每个可变操作至少验证“操作前 → 操作后 → 撤销 → 重做 → 保存 → 重开”。
- **逐帧观测**：编辑器首次出现、节点切换、宽度拖动、画布平移和工具栏出现期间，按 `requestAnimationFrame` 连续采集 50 帧；不得只看最终截图。
- **高频重复**：近期出现过竞态、漂移或闪烁的场景连续执行 20 次；一次失败即判失败，不用重跑成功覆盖失败。
- **故障注入**：模拟图片读取失败、Clipboard API 不可用、保存写入失败和旧选区延迟到达，确认安全降级且不破坏当前数据。
- **数据差异比较**：操作前后比较节点数、父子关系、UID、语义格式、视觉样式和资源字段，不只比较屏幕文字。
- **双端同源比较**：网页版和思源插件版使用相同输入数据执行同一编号用例；行为差异必须有明确产品规则，否则判回归。
- **视觉比较**：浅色、深色各留一组截图，比较文字层数量、边框、工具栏位置、不透明度和遮挡；禁止用肉眼印象代替关键几何断言。

每个自动化用例必须：

## 7. 执行档位

### 7.1 每次改动的快速档

适合每次进入共享核心的本地改动，目标时间 10～20 分钟：

1. 运行受影响领域的定向 Vitest。
2. 执行 `YM-DAILY-LIFE-001`、`LIFE-003`。
3. 执行 `YM-DAILY-EDIT-001`、`EDIT-004`、`EDIT-005`。
4. 执行 `YM-DAILY-SEL-001`、`SEL-004`。
5. 执行 `YM-DAILY-CLIP-003`、`CLIP-004`、`CLIP-006`。
6. 执行与本次改动直接相关的拖动、历史和视觉用例。
7. 确认 `YM-DAILY-VIEW-004` 无新增错误。

### 7.2 影响域档

适合日常功能开发和缺陷修复：

1. 快速档全部内容。
2. 本文中受影响章节的全部用例。
3. 相邻公共组件的一章用例。
4. 网页版真实 E2E。
5. 思源冷启动后的最小受影响域实机验证。
6. 最近问题对应场景连续执行 20 次。

### 7.3 发布级档

版本号、标签、Release 或 Pages 发布前必须：

1. 执行本文全部适用用例。
2. 执行 `docs/standards/回归验收清单.md` 全部发布级条目。
3. 执行完整自动门禁：

```powershell
npm run check:version
npm run test:structure
npm run check
npm test
npm run test:web
npm run test:offline
npm run verify:assets
npm run build:all
npm run test:e2e
node --check index.js
npm run release:build
npm run release:verify
```

4. 使用最终 ZIP 解包到全新目录，执行 `npm ci` 后重复完整验证。
5. 网页版和思源插件版分别执行双端实机矩阵。
6. 校验源构建、运行目录、ZIP、Release 和 Pages 版本、提交及 SHA-256 一致。

## 8. 通过标准与发布阻断

只有同时满足以下条件才能判定通过：

- 全部适用 P0 用例通过；P0 通过率必须为 100%。
- 自动门禁退出码全部为 0。
- 本轮没有新增跳过；既有跳过数量不得无解释增加。
- 近期竞态类场景连续 20 次通过，逐帧场景连续 50 帧无异常。
- 网页版与思源插件版最终数据和公开行为一致。
- 无新增未解释控制台错误、警告、页面错误或未处理 Promise。
- 保存重开、撤销重做、跨文件和历史导图都完成数据快照比对。
- 每个执行结果都绑定候选 SHA，有日志、截图、trace、录屏或哈希证据。

出现以下任一情况立即阻断合并或发布：

- 文字、图片、节点任一复制意图路由错误。
- Delete、Backspace、Ctrl+X、撤销或重做任一核心流程需要多次操作或误伤节点。
- 编辑、粘贴、切换节点、拖宽或工具栏出现任意一帧闪白、重影、空壳、错位或旧状态。
- 跨文件出现源 UID、丢结构、丢语义资源或错误继承整节点视觉样式。
- 保存重开后数据丢失，或一个文件的操作污染另一个文件。
- 导图与大纲、网页版与思源插件版行为不一致。
- 通过固定等待、重跑、跳过、删除断言或只看最终画面掩盖失败。
- 缺少候选提交、测试数据、执行步骤或证据，无法独立复现结论。
