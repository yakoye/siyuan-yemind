# YeMind 测试与验收

## 1. 质量阶段

1. 设计评审：核对双端共享边界、数据兼容、界面状态、错误处理和发布回滚。
2. 开发自测：每项行为先写失败测试，再做最小实现并运行相关领域测试。
3. 自动化测试：运行结构、语法、类型、主测试、网页测试、离线测试和资源检查。
4. 浏览器验收：使用 Chromium 覆盖桌面、小窗口和移动视口，保留失败 trace 与截图。
5. 思源验收：同步到指定运行目录，在真实思源宿主中打开旧图、新建图并验证保存重开。

任何核心用例失败、数据无法往返、运行目录版本不一致、发布包无法解压或线上资源 404，均阻断发布。

## 7. 性能与健壮性

- 工具栏和六点柄动画只改变 `opacity` 与 `transform`，不触发编辑区重排。
- 拖动和缩放期间不得出现持续长任务、未捕获异常或明显输入丢失。
- 图片加载失败、损坏导入、存储失败和只读拒绝必须保留可继续使用的编辑器。
- 自动化不得用固定长等待掩盖竞态，应等待明确的 DOM、保存或渲染状态。

## 8. 验收证据

发布验收记录必须包含测试命令、通过数量、跳过原因、浏览器视口、运行目录哈希、发布物大小与 SHA256、GitHub Actions 结果、Release 链接和 Pages 链接。失败时保存日志、trace、截图及最小复现步骤。

回滚时撤销发布标签和 Pages 部署，恢复上一稳定 Release；用户地图数据不参与插件文件同步或清理。

## 9. 下一版本

“复习与卡片”是 v1.4.0 候选范围。v1.3.0 只回归既有挖空/模糊功能，不新增复习计划、卡片模型、间隔算法或相关界面。
