# YeMind v1.9.0 上游优先文字编辑实施计划

> 设计：`docs/designs/2026-08-01-1912-v1.9.0-共享文字排版与可信发布-设计.md`
> 分支：`stabilization/shared-text-layout`
> 上游：`wanglin2/mind-map@e8e5ef9c41bc13ca7b13084e078123adff002242`

## 1. 执行原则

- 先建立当前 YeMind 的失败测试和纯上游基线，再迁移。
- 每个切片必须净删除代码；禁止新增 Coordinator、延时和像素补丁。
- 一次只替换一个职责，相关测试通过后独立本地 commit。
- 生成物不与源码 commit 混合；发布前只构建一次。

## 2. Task 1：冻结上游基线和差异清单

1. 保存上游 commit、版本和 `RichText.js` 哈希。
2. 自动比较 upstream 与 vendored runtime，只允许登记过的差异。
3. 增加纯上游最小页面，验证双击、输入、换行、宽度、Tab/Enter 和关闭。
4. 同文本同时跑“纯上游”和“YeMind 当前实现”，记录过程差异。

提交：`test: establish upstream rich text baseline`

## 3. Task 2：建立运行时 rich-text 适配器

1. 先写旧 plain 多行、空行、HTML 特殊字符、富文本、图片节点的可逆测试。
2. 加载时把运行时克隆转换为上游 `richText: true` HTML。
3. 保存、导入、导出分别验证语义不丢失；不得直接改坏用户原数据。
4. 旧复杂图冷启动、折叠展开、保存重开后内容一致。

提交：`refactor: normalize runtime text through upstream rich text`

## 4. Task 3：切换到上游编辑生命周期

1. 为当前闪白、重影、无光标、工具栏旧位置建立逐帧 RED 测试。
2. 创建实例级 body portal，使用上游 fixed 坐标。
3. 删除 `YeMindRichText` 对 `show/update/hide/focus` 的覆盖。
4. 删除 geometry-ready CSS 门禁和静态文字显隐交接。
5. 启用并验证上游 Web 使用的实时编辑路径；若性能失败，只允许在上游选项范围内调整，不恢复自研状态机。

提交：`refactor: adopt upstream rich text lifecycle`

## 5. Task 4：收敛 YeMind 薄适配器

保留并测试：

- 格式注册；
- Shift+Enter；
- 编辑器内 Delete/Backspace；
- Ctrl+A/C/X/V/Z/Y；
- 文字、节点、图片剪贴板类型；
- 选区工具栏事件；
- 实例作用域 DOM 查询。

目标：`YeMindRichText.ts` 不超过 500 行，且不包含几何、显隐和焦点重试状态机。

提交：`refactor: reduce YeMind rich text to integration adapter`

## 6. Task 5：删除协调器和旁路

按依赖顺序删除：

1. `canvasRichTextVisibility`。
2. `CanvasEditSessionCoordinator`。
3. 编辑期 `RenderedTextGeometryRepair`。
4. 可被上游插入流程替代的 `InsertedNodeEditCoordinator`。
5. `richTextGeometry` 中不再使用的坐标恢复。
6. `YeMindEditor.bindMapEvents()` 中对应 microtask/rAF、ready 事件和 repair 监听。

验收：净删除至少 1400 行，TypeScript、单元、Web E2E 全绿。

提交：`refactor: remove redundant canvas edit coordinators`

## 7. Task 6：复制粘贴与大纲矩阵

覆盖用户指定的全部组合：

- 复制选中后粘贴；复制、新建、粘贴；复制、新建、选中、粘贴。
- 导图编辑态/非编辑态 → 导图编辑态/非编辑态。
- 导图编辑态/非编辑态 → 大纲。
- 大纲 → 导图编辑态/非编辑态。
- 大纲 → 大纲。
- 同文件和跨文件各执行一次。
- 文字、节点、节点内图片、独立图片分别执行。
- 外部 ChatGPT/网页 HTML 不得泄漏 `StartFragment`、多余空行和外部样式。

提交：`test: complete clipboard and outline matrix`

## 8. Task 7：过程稳定性与性能矩阵

1. DPR 1/1.25/1.5/2。
2. 缩放 80/100/125/150%。
3. 中文、英文、混排、标点、Emoji、手动换行、长文本、自定义宽度。
4. 逐帧检查无空白、重影、位置跳变和旧工具栏帧。
5. 1000 节点输入、宽度拖动和父节点拖动记录帧时间；不得恢复逐字符 SVG `getBBox()` 热路径。

提交：`test: verify upstream lifecycle across host geometry matrix`

## 9. Task 8：可信构建、版本与发布

1. dirty release/runtime sync 直接失败。
2. clean commit 只构建一次。
3. 测试 Bundle、ZIP、解压目录、思源 runtime 哈希一致。
4. 版本更新为 `1.9.0`，更新 README、CHANGELOG、回归记录。
5. 思源冷启动和网页版执行完整发布级回归。
6. 本地提交通过后推送、发布 GitHub Release、验证 Pages。

任一 P0、剪贴板矩阵、逐帧稳定性或哈希门禁失败，停止发布并回到对应 Task。
