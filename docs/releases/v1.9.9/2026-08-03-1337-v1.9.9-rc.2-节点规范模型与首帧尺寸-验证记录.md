# v1.9.9-rc.2 节点规范模型与首帧尺寸验证记录

## 目标

修复三个同源问题：导图加载后节点框与文字不匹配、root 内容裁切，以及节点在大纲编辑后无法立即拖动宽度。该版本为 `v1.9.9` 的第二个候选版；用户完成思源实机验证前不得提升为稳定版。

## 根因

同一节点同时存在三份语义不同的数据：仓储中的纯文本节点、传给 `simple-mind-map` 的临时富文本副本，以及大纲提交生成的投影树。加载时只转换临时副本，仓储和 `current.data` 没有迁移；大纲提交后又会用投影树覆盖当前文档。轻微拖宽或在画布编辑一次会触发内核重新测量并保存富文本，因此表现为“操作一下才恢复”。

## 修复

- 加载时把完整节点树一次性迁移为上游富文本规范模型，并保存到仓储。
- 迁移返回明确的 `changed` 状态，重复加载保持幂等，不重复改写数据。
- 大纲纯文本提交统一转换为富文本命令，不再走另一套 SVG 纯文本测量路径。
- 大纲单节点文本仍使用原生命令；多节点文本修改从内核 canonical tree 克隆后只写入目标 UID，再以一次可撤销的整树事务提交。未修改节点的文本和元数据保持不变，失败时不会留下半成功状态。
- 大纲提交成功后从导图内核回读规范树，不再用大纲投影覆盖 `current.data`。
- 保留文本内容、多行结构、`customTextWidth`、图片和其他节点字段。

## 回归用例

| 用例 | 预期 |
|---|---|
| 保存的纯文本 custom-width 节点首次加载 | 文字完整位于节点框内，不经编辑或拖宽 |
| 长 root 节点首次加载 | 内容不裁切，节点框覆盖完整文字 |
| 小尺寸宿主恢复为正常尺寸 | 首次可见布局正确 |
| 大纲修改节点后不刷新、立即回到导图拖宽 | 拖动手柄可用且宽度发生变化 |
| 多节点大纲文本事务 | 一次提交、可整体撤销；任一目标无效时零副作用 |
| 旧仓储迁移 | 内容不丢失，仓储与运行时均为 `richText:true` |
| 重复迁移 | 第二次 `changed:false`，数据不再变化 |
