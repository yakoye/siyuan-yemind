## 根因与实现边界

1. SVG 文本 `getBBox()` 返回的是字形墨迹边界，不是节点排版框。首次打开编辑器时用墨迹边界参与缩放和居中，会造成多行文本向右跳、短暂压缩，再被后续布局纠正。本轮改用节点保存的逻辑宽高与 CTM 重建屏幕排版框，并修正上游 SVG 文本组以逻辑宽高居中。
2. 编辑器几何尚未完成时就显示，会暴露中间帧。本轮增加明确的 geometry-ready 状态，只在首帧定位完成后显示编辑层。
3. 过去复制节点主要依赖纯文本或当前实例状态，跨文件时会丢失层级、备注，或把来源主题样式带到目标文件。本轮新增共享节点剪贴板协议：保留语义内容和层级，移除来源 UID；跨文件剥离表现样式，同文件保留样式。
4. Windows 剪贴板的 CRLF 与末尾换行会让结构化载荷和纯文本校验不一致。本轮在协议入口统一换行后再匹配，避免画布与大纲互贴时退化成普通文本。
5. 大纲粘贴不再逐行模拟输入，而是以目标行节点为锚点调用一次原生多子节点事务；因此撤销、重做、保存和重开使用同一命令链。

补充约束：

- 多选包含父子节点时只复制最高层选中祖先，子节点不会重复。
- 同文件保留节点样式；跨文件移除来源边框、填充、自定义宽度和字体等表现属性。
- 加粗、公式、备注、图片等语义内容随节点复制。
- 复制后的所有节点生成新 UID，不覆盖来源节点。
- 大纲到大纲的跨文件粘贴已验证撤销、重做、保存与重载。
