# YeMind v1.9.8 中间节点拖动预览与飞线回归记录

## 1. 问题结论

- 时间：2026-08-03 10:55 +08:00
- 分支：`stabilization/shared-text-layout`
- 修改前正式版本：`v1.9.7`（`64aa8d70-clean`）
- 目标版本：`v1.9.8`
- 执行档位：发布级

实机反馈确认了稳定分界：叶子节点拖动正常，所有中间节点拖动异常。因此问题不在候选父节点算法，而在中间节点独有的预览分支。

## 2. 根因与精简修复

`simple-mind-map` 的 `Drag.createCloneNode()` 已经为所有节点创建定位语义一致的单节点克隆。YeMind 随后仅在节点包含后代时调用 `replaceSingleNodeCloneWithSubtree()`，删除原克隆并新建包含后代和连接线的 SVG 包装组。

这个包装组改变了克隆的包围盒与局部坐标系；虚线端点继续按上游单节点坐标读取，因此中间节点会从错误位置飞出虚线，拖动预览也与叶子节点不一致。

v1.9.8 删除整个子树预览实现和对应样式分支，不新增第二套几何算法：

- 所有节点直接保留上游单节点克隆；
- 仅给克隆添加语义类 `ymz-drag-node-preview`；
- 单节点边框固定为 `#8de2ce`；
- 候选父节点仍复用上游 `highlight()` / `closeHighlight()`；
- 绿色虚线仍在上游完成克隆定位后的有效移动帧中绘制；
- 后代不作为拖动幽灵绘制，但最终结构提交仍由上游整棵子树移动。

本次净删除超过新增，消除了“叶子节点一条路径、中间节点另一条路径”的根因。

## 3. 自动化门禁

- 中间节点创建拖动克隆时不得调用 `otherDraw.group()` 新建子树包装层。
- 一级中间节点与深层中间节点都只能存在一个 `.ymz-drag-node-preview`。
- 预览内部不得嵌套额外 `.smm-node`，其 `.smm-node-shape` 计算描边必须为 `rgb(141, 226, 206)`。
- 首次有效移动前不得绘制目标虚线；移动后的每个采样帧坐标必须有限且不得触碰居中画布边缘。
- 候选父节点同时具有 YeMind 语义类和上游高亮类，释放后两者全部清理。
- 结构提交后，中间节点及其后代 UID 层级关系必须完整移动。
