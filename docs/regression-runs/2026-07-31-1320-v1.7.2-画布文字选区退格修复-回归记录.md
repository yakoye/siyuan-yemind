## 用户报告问题（v1.7.1 部署到真实思源后复测）

用户在完全重启思源、确认 v1.7.1 已生效后，报告以下三个现象（均发生在导图画布节点文字编辑中）：

1. 双击进入编辑，开始输入，整个节点文字不停来回跳。
2. 使用删除键：光标跳到刚输入文字前面，把之前的文字都删了，刚输入的留下了。
3. 拖动节点宽度手柄拉长/缩短，文字不停跳。

## 复现方式与结论

在标准网页版真实 Chromium 环境中逐项复现：

- 现象 1（连续输入文字跳动）：多次尝试（长中英混排文字、真实 `keyboard.type`、MutationObserver 逐帧监测编辑层位置）均未能复现明显跳动（>2px 位置突变次数为 0）。真实思源客户端环境（含 SiYuan 自带字体、`--b3-font-family` 等 CSS 变量）无法从当前沙箱环境直接接入调试（详见"无法执行的验证"）。**结论：尚未确认**，但下方现象 2 的修复很可能是用户观察到"跳动"的主要或全部来源——大段文字被误删后节点会剧烈收缩重排，观感上与"跳动"一致。
- 现象 2（删除键误删）：**已确认并修复**，见下方根因分析，且已用确定性方式（真实指针点击定位光标、真实 `keyboard.type`、真实 `Backspace`）稳定复现。
- 现象 3（宽度拖动文字跳动）：现有回归 `width-handle drag grows the live node monotonically without disappearing or jumping` 覆盖同一诉求且持续通过；未发现独立于现象 2 的额外拖动期问题。**结论：尚未确认存在独立缺陷**，建议在真实思源中人工复验。

## 根因分析（现象 2）

`node_modules/quill/core/selection.js` 的 `Selection#update()`：

```js
const args = [Emitter.events.SELECTION_CHANGE, cloneDeep(this.lastRange), cloneDeep(oldRange), source];
this.emitter.emit(Emitter.events.EDITOR_CHANGE, ...args);
if (source !== Emitter.sources.SILENT) {
  this.emitter.emit(...args);
}
```

而 `SCROLL_BEFORE_UPDATE` 处理器在检测到"这次原生选区变化是由输入触发的"（`triggeredByTyping`，通过判断伴随的 DOM mutation 类型得出）时，会显式调用 `this.update(Emitter.sources.SILENT)`。也就是说：**Quill 认为"输入文字导致光标前移"这件事，本来就不需要单独通知外部监听者**——它只更新 Quill 内部自己的 `lastRange`，并广播范围更大的 `editor-change`，**故意不触发**公开的 `selection-change` 事件。

`src/editor/YeMindRichText.ts` 中 `this.range` / `this.lastRange`（"最近一次已知选区"缓存，用于 Delete/Backspace/复制/剪切在焦点被工具栏等外部元素抢走时仍能作用于正确目标，这是 v1.6.2 引入的既有正确设计）**只从 `quill.on('selection-change', ...)` 刷新**。因此：

1. 用户双击节点 → `focus()` 触发"全选"，`this.range = {index:0, length:全文长度}`。
2. 用户真实点击文字中间某处，光标折叠到那里 → 这是一次真实的用户选区动作，Quill **会**触发 `selection-change` → 处理器执行 `this.lastRange = this.range`（把第 1 步的"全选"结果存进 `lastRange`），`this.range = null`。
3. 用户开始输入新字符 → 光标随输入自然前移，但按上述 Quill 内部逻辑，这次不会触发 `selection-change` → `this.range` / `this.lastRange` **不再更新**，`lastRange` 仍然停留在第 1 步"全选"时的范围。
4. 用户按下 Backspace → `deleteCurrentSelection()` 先查询 Quill 当前真实选区（是折叠的，长度为 0），查不到就回退到 `this.range ?? this.lastRange`，取到的正是第 1 步遗留的"全选原文"范围 → 一次 Backspace 删除了几乎整个节点原文，只保留了范围之外残留的少量文字。

已用 Playwright 精确复现：点击长文字节点中间空白处放置折叠光标（经 `window.getSelection()` 验证真实落点）→ 输入 `XYZ` → 按一次 Backspace → 结果只剩最后 3 个字符（`足够宽`），其余全部被误删。

## 对应修复

`src/editor/YeMindRichText.ts`：在 Quill `'text-change'` 事件处理器中，当 `source === Quill.sources.USER` 时，除原有的 `markNodeTextEditedData(...)` 外，追加清空 `this.range = null; this.lastRange = null;`。

理由：只要发生了一次用户驱动的文字变更（输入、粘贴、格式化等都会触发 `text-change`），此前缓存的"非折叠选区"就一定已经过时——要么该区域文字已不存在，要么用户的意图已经从"操作那段选区"变成"在新光标处继续编辑"。让缓存在文字变更时立即失效，比等待一个 Quill 可能永远不会补发的 `selection-change`更安全。

已确认不影响既有"焦点被工具栏抢走后 Delete 仍作用于已保存选区"这一正确功能（该场景中用户点选区、点工具栏按钮之间没有发生任何 `text-change`，缓存依然有效）——对应回归 `canvas Delete routes to the saved text selection after the host steals DOM focus`、`canvas partial selection cuts in one Ctrl+X transaction...`、`deleting a full canvas text selection remains one undoable text transaction` 均继续通过。
