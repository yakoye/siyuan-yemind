## 背景

v1.7.1 至 v1.7.6 六个版本反复围绕同一个架构问题打补丁：编辑期间每次按键都重建 SVG 静态文字（`node.createTextNode()`），先后修了焦点丢失、退格误删、宽度拖动重影、`max-width` 不刷新、`renderLine(true)` 不必要的深度递归、最后给提交本身加 160ms 防抖——防抖只是延迟了症状，没有消除根因。

用户在拿到 v1.7.6 后做了一次完整的架构复盘（见对话记录），指出四个根本矛盾：① 上游已关闭实时渲染（`openRealtimeRenderOnNodeTextEdit: false`），YeMind 自己又建了一套更复杂的实时渲染；② 编辑期间同时维护 SVG 静态文字和 Quill 两套文字层；③ 编辑器定位靠一个永久 `requestAnimationFrame` 循环补偿，而不是事件驱动；④ SVG 与 Quill 排版参数不统一导致换行不一致。用户明确要求"不要再发 v1.7.7 补丁，开一个专门分支做编辑生命周期精简"。

写实施计划前，对用户提出的每一条关键判断都做了源码级核实（见 `docs/superpowers/plans/2026-07-31-canvas-text-edit-stabilization.md` 的"背景与验证依据"一节），全部核实为真，随后按用户选择的"一次性全部完成"执行了完整的 10 项改动，用 `superpowers:subagent-driven-development` 流程（每个任务：实现子代理 → 独立验证子代理复核规格符合性 → 独立代码质量审查子代理，发现问题打回修复、重新审查，直到通过）逐任务推进。

## 有意的行为取舍（非缺陷，需人工验证时留意）

- **编辑过程中节点边框不再实时增长**——只在编辑结束提交时更新一次。
- **粘贴不再有单独的立即提交分支**——粘贴内容和其它编辑一样，只在关闭编辑时一次性提交。
- **拖拽期间/文字编辑期间，节点快捷操作按钮（+/-/展开收起）会短暂隐藏**，动作结束后自动恢复。

## 需要人工验证

完整重启 SiYuan 后，请在真实的、带较大子树/长文本的节点上重点验证：

1. 连续快速打字（含中文输入法）是否不再出现文字跳动/偏移/重影——这是本轮从 v1.7.1 起持续修复的核心问题，这次是从根上删除了触发源，理论上应该彻底消失。
2. 双击一个已有内容的节点，是否只是把光标放在末尾，而不是全选文字。
3. 双击一个从未编辑过的新节点，是否仍然自动全选。
4. 拖动节点宽度手柄，编辑层是否正确跟随。
5. 拖拽一个节点时，附近节点的快捷操作按钮是否短暂隐藏、松手后正确恢复。
6. 长文本节点（接近换行边界）双击进入编辑，是否不再出现"最后一个字掉到下一行"的排版不一致。
7. 编辑过程中节点边框不再实时增长（这是有意的取舍，不是回归）。

如果方便，建议用 Chrome Performance 面板录制一次 trace，对比连续输入期间是否不再出现 `commitTextEdit → createTextNode → getBBox` 这条调用链——这是用户在推动这次重构时提出的验收基线。
