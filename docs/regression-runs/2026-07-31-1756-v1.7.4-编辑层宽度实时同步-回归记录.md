## 用户提供的关键证据

用户直接从真实思源客户端的浏览器 DevTools 中复制了两组问题节点的完整 DOM：

1. 一个长文本节点被拖动到极窄宽度后，其画布 SVG 静态文字呈现为 `data-width="20"`、几乎一个字符一行的竖长条（约 30 行，高 539px）；同时正在编辑的 Quill 层 `min-height: 539px`，但内容 `<p>PCIe RAS Reliability / Availability / Serviceability 可靠性 / 可用性 / 可维护性</p>` 仍按一整行排布。
2. 另一个三行节点，画布 SVG 已正确 `visibility:hidden!important`（确认 v1.7.3 的隐藏修复生效），大纲行 `data-outline-editor` 显示同样文字——用户据此判断"跳动是因为文本出现了两次"。

第 1 组证据是本轮定位到新根因的关键。第 2 组证据实际印证画布层隐藏逻辑已经正确工作；大纲行与画布共享同一份数据、各自独立渲染是既有设计（`ARCHITECTURE.md`："Canvas and outline own focus independently"），并非缺陷，已向用户说明。

## 根因分析（新发现）

`vendor/simple-mind-map-runtime/src/plugins/RichText.js` 的 `showEditText()` **只在编辑刚打开的那一刻**设置一次编辑层的 `max-width`：

```js
textAutoWrapWidth = node.hasCustomWidth() ? node.customTextWidth : textAutoWrapWidth
...
this.textEditNode.style.maxWidth = textAutoWrapWidth + paddingX * 2 + 'px'
```

而 `src/editor/YeMindRichText.ts` 的 `applyEditorGeometry()`——在每次按键提交和每个宽度拖动帧都会执行——只刷新 `min-width`/`min-height`/外边距，**从未刷新 `max-width`**。

真实复现路径（与用户描述完全一致："文字全选,然后拖动节点长短"）：

1. 双击节点进入编辑，此时 `max-width` 按打开时的宽度设置一次。
2. 用户全选文字，再拖动宽度手柄把节点收窄——`node.customTextWidth` 随拖动持续变小。
3. 画布静态 SVG 文字在每次提交时都用 `createTextNode()` 重新按**当前**宽度换行（变成很多短行），但 Quill 编辑层的 `max-width` 仍停留在打开编辑那一刻的旧值，继续按**旧的、更宽**的宽度排版（可能只需一行）。
4. 两种排版对同一段文字产生完全不同的换行结果。一旦静态 SVG 文字因任何原因短暂可见（例如 v1.7.3 已修复的拖动可见性被清除问题，或本身未完全解决的纯打字闪烁），两种截然不同形状的排版叠在一起，就是用户看到的"文字重影/跳动"。

## 对应修复

`src/editor/YeMindRichText.ts`：`applyEditorGeometry()` 现在每次调用都重新计算 `max-width`（复用与上游 `showEditText()` 相同的 `node.hasCustomWidth() ? node.customTextWidth : textAutoWrapWidth` 规则），不再只在打开时设置一次。位置、外边距的实时刷新逻辑不变。

## 新增失败测试

`tests/e2e/web-rich-text-outline.spec.ts` 新增 `the live Quill editor rewraps to the node's current width after a width-drag performed while text is selected and editing`：真实双击进入编辑、全选文字、真实拖动宽度手柄大幅收窄，断言编辑层 `max-width` 跟随新宽度而不是停留在打开编辑时的旧值。已手动临时禁用修复代码确认此测试失败（收到的宽度等于拖动前的值），恢复修复后通过。
