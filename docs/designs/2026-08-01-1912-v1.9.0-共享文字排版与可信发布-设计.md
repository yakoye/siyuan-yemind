# YeMind v1.9.0 上游优先文字编辑架构设计

## 1. 决策

YeMind v1.9.0 不再继续扩展“SVG 静态文字 + Quill 编辑文字 + 多协调器交接”的架构，改为以上游 `wanglin2/mind-map` 当前主分支为运行时基线：

- 运行时节点文字统一使用上游 `richText` HTML 渲染。
- 静态态和编辑态使用同一套浏览器 HTML/CSS 排版。
- `showEditText()`、`updateTextEditNode()`、`hideEditText()`、`focus()` 由上游 `RichText` 生命周期负责。
- YeMind 只保留思源集成、格式扩展、剪贴板语义和旧数据兼容。
- 不再新增 Coordinator、固定延时、像素补偿或多层 `requestAnimationFrame`。

参考基线：

- 上游仓库：`wanglin2/mind-map`
- 上游提交：`e8e5ef9c41bc13ca7b13084e078123adff002242`
- `simple-mind-map`：`0.14.0-fix.3`

## 2. 根因证据

当前 vendored `simple-mind-map/src/plugins/RichText.js` 与上游文件一致，问题不在 vendored `RichText` 本体。

额外复杂度位于 YeMind 外层：

| 文件 | 当前行数 | 处置 |
| --- | ---: | --- |
| `src/editor/YeMindRichText.ts` | 1308 | 收敛为薄适配器 |
| `src/editor/CanvasEditSessionCoordinator.ts` | 126 | 删除 |
| `src/editor/canvasRichTextVisibility.ts` | 132 | 删除 |
| `src/editor/RenderedTextGeometryRepair.ts` | 160 | 删除或降为非编辑期工具 |
| `src/editor/InsertedNodeEditCoordinator.ts` | 181 | 由上游插入编辑流程替代 |
| `src/editor/richTextGeometry.ts` | 332 | 删除大部分自定义坐标恢复 |

合计约 2239 行。它们形成了多条相互竞争的状态链：

```text
上游 RichText 生命周期
  + YeMind 会话阶段
  + 静态文字显隐
  + 编辑框几何门禁
  + 插入节点延迟打开
  + 节点树重绘后的几何修复
  + 焦点租约
```

上游 Web 的关键差异是：节点统一转换为 `richText`，静态态与编辑态都使用 HTML/CSS；YeMind 保留 plain SVG 文字后，必须在两套排版引擎之间切层，才产生闪白、重影、换行变化、坐标偏移和焦点空档。

## 3. 架构边界

### 3.1 运行时模型

画布运行时树必须满足：

```ts
interface RuntimeTextData {
  text: string;       // HTML
  richText: true;
}
```

旧文件中的 plain text 在加载到画布前转换为安全 HTML，保留：

- 手动换行和空行；
- HTML 转义；
- 图片、图标、待办、备注、批注、卡片和关联数据；
- 原有节点 UID、顺序、结构、样式和自定义宽度。

不得在编辑期间来回转换 plain/rich。存储、导入和导出边界负责格式兼容。

### 3.2 编辑生命周期

YeMind 不再覆盖上游四个核心方法：

- `showEditText()`
- `updateTextEditNode()`
- `hideEditText()`
- `focus()`

编辑框由上游创建、显示、定位、聚焦、提交和销毁。YeMind 不隐藏静态文字、不维护 `data-yemind-geometry-ready`，也不在打开事务中启动额外几何修复。

### 3.3 覆盖层位置

使用每个 YeMind 编辑器实例自己的 body portal，保持上游 `position: fixed` 坐标语义。portal 必须：

- 有唯一 owner id；
- 编辑器销毁时移除；
- 不共享全局选择器；
- 受当前标签页 z-index 和可见性控制；
- 不影响其他 YeMind 标签页和思源编辑器。

### 3.4 允许保留的扩展

只允许保留以下职责：

1. Quill 字体、字号、链接、代码、公式和模糊格式注册。
2. 节点文字/图片/大纲/跨文件剪贴板类型判定。
3. Shift+Enter、Delete、Backspace、Ctrl+A/C/X/V/Z/Y 的编辑器语义。
4. 旧 plain 数据与运行时 rich-text 数据的可逆兼容。
5. 所有 DOM 查询限定在当前编辑器实例。
6. 富文本选区工具栏监听上游 Quill 选区事件，不参与编辑器显示和定位。

## 4. 删除清单

迁移完成后删除：

- `CanvasEditSessionCoordinator` 及相关 phase/selection revision。
- `canvasRichTextVisibility` 及 SVG 文字 `visibility`/`aria-hidden` 交接。
- `.smm-richtext-node-edit-wrap:not([data-yemind-geometry-ready="true"])` CSS 门禁。
- `YeMindRichText` 中 opening geometry、placement frame、ResizeObserver、focus lease、旧节点恢复和坐标回退。
- `before_show_text_edit` 中 microtask/rAF 显隐同步。
- 编辑会话期间的 `RenderedTextGeometryRepair`。
- 能由上游 isInserting/Enter/Tab 流程直接承担的 `InsertedNodeEditCoordinator`。

删除目标：相对当前分支净减少至少 1400 行编辑生命周期代码。若未达到，需要在回归记录中逐项说明保留理由。

## 5. 上游移植规则

- 首选直接调用或继承上游，不复制粘贴后再维护一份近似实现。
- 上游存在实例作用域缺陷时，只提交最小 vendor 修复并补契约测试，例如全局 `document.querySelector()` 改为当前实例查询。
- 上游行为与 YeMind 产品要求冲突时，在边界适配，不在核心生命周期中插入旁路状态机。
- vendored runtime 的每项差异必须能通过 `git diff --no-index` 解释，并在文档登记。

## 6. 测试不变量

核心验收不再只检查最终状态，必须检查过程：

- 双击后同一次操作立即出现光标，首个按键不丢失。
- 打开、切换、关闭编辑器无空白帧、重影帧和旧位置工具栏帧。
- 静态态与编辑态逐行字符一致。
- 输入、粘贴、删除、撤销、重做时节点边框与文字同步。
- Tab/Enter 新节点首帧已有默认文字和编辑框。
- 宽度拖动过程文字、节点、子树不跳动。
- 导图/大纲、同文件/跨文件、文字/节点/图片剪贴板矩阵全部通过。
- DPR 1/1.25/1.5/2 与缩放 80/100/125/150% 通过。

## 7. 发布不变量

继续执行可信发布要求：

```text
clean source commit
→ build once
→ test that bundle
→ package without rebuild
→ extract and hash
→ deploy extracted bundle
→ runtime hash equals tested bundle hash
```

dirty 构建不得进入正式 release。测试 Bundle、ZIP Bundle、解压 Bundle 和思源运行目录 Bundle 的 SHA-256 必须完全一致。

## 8. 版本与回滚

该迁移改变运行时文字模型和编辑生命周期，目标版本为 `v1.9.0`。首次候选发布前必须保留旧文件备份和可逆数据转换测试；回滚以完整 ZIP 为单位，不允许只覆盖 `index.js`。
