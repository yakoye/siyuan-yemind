# YeMind v1.9.0 共享文字排版与可信发布设计

## 1. 背景与结论

本设计以 2026-08-01 的真实 Trace、当前 `v1.8.1` 源码和思源运行目录核对结果为依据。

已经确认：

- `v1.8.0` 删除编辑期逐字符 SVG 重建是正确方向，当前问题不再是每次输入触发大量 `getBBox()`。
- 录制 Trace 时运行的是 `70f84dbd-dirty-09b9b006`，不是 GitHub 最终候选构建。
- 当前思源运行目录已经是 `v1.8.1 · f078f29c-clean`，重新实测后编辑框长时间空白没有复现。因此“编辑框空白”当前按旧 dirty 构建/部署不一致处理，不能继续拿旧 Trace 证明 f078 仍存在零可见层。
- 静态 SVG 普通文字通过 `maxWidth` 决定换行，但只把换行后的墨迹宽度写入 `data-width`；`YeMindRichText` 又把 `data-width` 当作编辑器内容盒宽度。该语义错误在当前源码中客观存在。
- 静态 SVG 与 HTML/Quill 使用不同排版引擎，即使宽度相同，中文禁则、字体回退、字素、亚像素取整等仍可能造成换行差异。
- `RenderedTextGeometryRepair` 没有编辑会话保护，修复后还会调用全图 `mindMap.render()`，与“编辑期间不触碰静态 SVG”的目标冲突。
- 当前构建标识包含构建时 Git HEAD；构建后再提交生成产物会造成仓库根 Bundle、测试 Bundle、ZIP Bundle 与运行目录 Bundle 的身份漂移，发布链路不可作为同一二进制证明。

本次没有与 `docs/standards/回归验收清单.md` 冲突。清单允许在有上游通用根因证据并补回归测试时修改 vendored runtime；本次已具备源码、Trace 和实机证据。

## 2. 目标与非目标

### 2.1 目标

1. 为普通文字建立明确、可测试的排版数据契约，拆分墨迹宽度、换行宽度和内容盒宽度。
2. 静态 SVG 行划分与 HTML 编辑器使用同一个浏览器 DOM 排版结果。
3. 编辑打开、关闭和节点切换期间，每帧至少有一层文字可见；只有真实失败测试证明 f078 仍违反该不变量时才改写交接生命周期。
4. 编辑期间禁止几何修复和无关全图重绘。
5. 最终被测试、打包、解压、部署的 Bundle 必须是同一字节序列并可用 SHA-256 证明。
6. 插件版和网页版继续使用同一 `src/` 与 vendored runtime 实现。

### 2.2 非目标

- 不改导图数据格式中的节点 UID、附件、主题、样式或富文本语义。
- 不把所有普通文字直接改成 `foreignObject`；该方案保留为未来兼容性评估项。
- 不使用 `+1px`、固定延时、扩大容差或多层 `requestAnimationFrame` 掩盖排版差异。
- 不根据旧 dirty Trace 直接重写完整编辑生命周期。
- 不修改与文字布局、编辑会话、几何修复和发布链路无关的 UI。

## 3. 方案比较

### 3.1 方案 A：共享 DOM 排版，静态仍输出 SVG（采用）

浏览器隐藏测量层按与编辑器相同的 CSS 完成换行，输出视觉行；静态层再用这些视觉行创建 SVG `<text>/<tspan>`。

优点：

- 静态和编辑态共享浏览器排版规则。
- 保留普通 SVG 文字的导出兼容性。
- 可以缓存布局结果并消除逐前缀 SVG `getBBox()`。

代价：

- 需要维护隐藏测量宿主、字体加载失效和字素分组。
- 测量结果依赖 DOM，纯 Node 单元测试需注入测量器或使用 jsdom/浏览器契约测试。

### 3.2 方案 B：普通静态文字改用 `foreignObject`（暂不采用）

静态和编辑态都使用 HTML，换行一致性最好，但 SVG 外部查看器、PDF/PNG 导出和大节点 DOM 性能风险更高。本次不承担该兼容性迁移。

### 3.3 方案 C：继续修正像素、延时和容差（拒绝）

该方案不能消除宽度语义错误和双排版引擎差异，会继续形成针对单个文本的补丁。

## 4. 统一排版数据契约

在 vendored runtime 中引入明确结果：

```ts
interface PlainTextLayoutResult {
  node: SVGElement;
  inkWidth: number;
  wrapWidth: number;
  contentWidth: number;
  height: number;
  hardLines: string[];
  visualLines: string[];
  autoWrapped: boolean;
}
```

字段规则：

- `inkWidth`：最终最长视觉行的实际墨迹宽度。
- `wrapWidth`：自动换行判定使用的逻辑上限；自定义宽度节点取 `customTextWidth`，普通节点取 `textAutoWrapWidth`。
- `contentWidth`：静态文字和编辑器共同使用的内容盒宽度。自定义宽度节点等于 `wrapWidth`；自动宽度节点等于不超过 `wrapWidth` 的实际布局内容盒宽度，但其视觉行必须来自同一次 DOM 布局结果。
- `hardLines`：用户原始换行，不丢失空行。
- `visualLines`：浏览器布局后的视觉行，静态 SVG 与编辑验收均以此为准。
- `autoWrapped`：至少一个硬行被浏览器自动拆成多行时为 `true`。

SVG 需要写入：

```text
data-ink-width
data-wrap-width
data-content-width
data-auto-wrapped
data-width
```

兼容规则：`data-width` 在 v1.9.0 内继续表示节点当前布局宽度，旧调用方逐步迁移到明确字段；读取旧图或旧运行时节点时，缺失新字段必须有可预测回退，不能使节点塌缩。

## 5. 共享 DOM 排版器

### 5.1 API

```ts
measurePlainTextLayout(input: PlainTextLayoutInput): PlainTextLayoutMetrics
```

输入必须包含文本、内容宽度、字体族、字号、字重、字形、行高、字间距、`white-space`、`word-break`、`overflow-wrap` 和 `line-break`。

### 5.2 测量宿主

测量宿主挂在编辑器根容器中，必须满足：

- 绝对定位到不可见区域。
- `visibility: hidden`，不使用 `display: none`。
- `pointer-events: none`。
- 使用与 `.ql-editor` 相同的文字 CSS token。
- 销毁编辑器时清理 DOM、字体监听和缓存。

### 5.3 字素与视觉行

- 使用 `Intl.Segmenter(..., { granularity: 'grapheme' })`；不再使用 `split('')`。
- 每个字素进入独立 span，通过 `getClientRects()` 或稳定的 `offsetTop` 分组生成 `visualLines`。
- 手动换行先形成 `hardLines`，再分别布局，空硬行必须保留。
- 如果环境不支持 `Intl.Segmenter`，使用按 Unicode code point 的回退，禁止退回 UTF-16 code unit 拆分。

### 5.4 缓存和失效

缓存键包含文本、宽度、全部字体参数、换行参数、设备字体版本。以下事件使相关缓存失效：

- `document.fonts.loadingdone`。
- 主题或字体 token 变化。
- 节点文字、字号、字体、字重、字形、字间距、行高或自定义宽度变化。

缓存必须有大小上限；编辑器销毁时清理，不能形成跨文档泄漏。

## 6. 编辑器宽度与生命周期

### 6.1 v1.9.0 宽度来源

`YeMindRichText.applyEditorGeometry()` 不再把旧 `data-width` 解释为换行上限。优先读取：

1. `data-content-width`；
2. 共享排版结果；
3. 旧节点兼容回退 `data-width`；
4. `customTextWidth` 或 `textAutoWrapWidth`。

编辑器和测量宿主使用同一 `box-sizing`、padding、font、line-height 与换行 CSS。

### 6.2 原子交接的进入条件

先新增 f078/候选构建的逐帧失败测试：

```text
staticVisible || editorVisible
```

覆盖打开、关闭和 A→B 切换。只有测试在当前干净构建上确实失败，才把 `CanvasEditSessionCoordinator` 扩展为：

```ts
type CanvasEditSessionPhase =
  | 'idle'
  | 'preparing'
  | 'active'
  | 'committing'
  | 'aborting';
```

并拆分 `prepareEditText()`、`activateEditText()`、`deactivateEditText()`。如果当前构建测试持续通过，则只删除旧的重复同步和增加不变量监控，不进行无证据的大规模生命周期改写。

### 6.3 交接状态操作

禁止继续使用“每次先 restore 再 hide”的同步函数。若进入生命周期重写，操作必须是幂等状态设置：

- `prepareTextLayerHandoff(uid, sessionId)`
- `activateEditorLayer(uid, sessionId)`
- `restoreStaticLayer(uid, sessionId)`
- `finishTextLayerHandoff(uid, sessionId)`
- `abortTextLayerHandoff(uid, sessionId)`

每次通过 UID 重新查询 live DOM，不把旧 SVG 元素引用当作唯一恢复依据。

## 7. 编辑期渲染隔离

`RenderedTextGeometryRepair` 必须读取当前编辑会话。在 `preparing/opening/active/committing/closing/aborting` 任一阶段直接返回，不遍历树、不修改宽度、不调用 `reRender()` 或 `mindMap.render()`。

非编辑期修复改为：

- 同一 render revision 最多修复一次。
- 只重绘受影响节点、必要祖先和连线。
- 禁止修复再次触发同 revision 修复。
- 只有无法局部布局且有明确测试证据时才允许全图 render。

## 8. 可信发布链路

### 8.1 问题

当前 Bundle 嵌入构建时 Git HEAD。把 Bundle 再提交后 HEAD 改变，仓库内已提交 Bundle 会天然落后一笔；在 CI 重建又产生另一份标识和构建时间，因此“源码提交中的 Bundle”和“该提交构建的 Bundle”不能逐字节一致。

### 8.2 新契约

1. 最终发布以干净 checkout 的源提交为输入。
2. `sourceBuildId` 表示输入提交和源树状态，不要求生成产物再提交回同一提交。
3. 发布 ZIP 是正式可部署产物；运行目录只能从已验证 ZIP 解压同步。
4. 测试 Bundle、ZIP 内 Bundle、解压验证 Bundle、运行目录 Bundle 的 SHA-256 必须一致。
5. Manifest 同时记录 `sourceCommit`、`sourceTree`、`bundleSha256`、构建环境和构建时间。
6. 禁止 dirty 构建进入 release 或 runtime sync；开发预览可以 dirty，但必须显示 dirty 标识。

### 8.3 流程

```text
clean checkout
→ npm ci
→ 源码测试
→ build final Bundle once
→ 对该 Bundle 跑 E2E
→ package without rebuilding
→ verify ZIP
→ 解压 ZIP
→ 对解压 Bundle 跑必要测试
→ 从解压目录同步 runtime
→ 校验 runtime SHA-256
```

## 9. 兼容性与错误处理

- 旧节点缺失新 `data-*` 属性时使用兼容回退，并在下一次正常渲染补齐，不修改持久化数据格式。
- 字体尚未加载时可先使用当前字体布局，但 `loadingdone` 后只执行一次受影响节点重排。
- DOM 测量返回 0 或宿主不可见时不得覆盖已有几何；记录诊断并延后到可见布局事件。
- Emoji、组合字符、变体选择符和生僻字符不得拆成半个字素。
- 测量失败、编辑会话中止和节点被删除都必须恢复至少一层可见文字并清理临时状态。
- 发布校验发现 dirty、提交不一致或哈希不一致时直接失败，不继续同步运行目录。

## 10. 测试与验收

新增稳定用例：

- `YM-TEXT-022`：静态与编辑态逐行字符内容完全一致。
- `YM-TEXT-023`：打开、关闭、A→B 切换的每一采样帧至少一层文字可见。
- `YM-TEXT-024`：中文、英文、混排、标点、Emoji、手动换行、自定义宽度和自动宽度共用布局契约。
- `YM-TEXT-025`：DPR 1/1.25/1.5/2 与画布缩放 80/100/125/150% 下行划分不变。
- `YM-TEXT-026`：编辑准备、激活、焦点和选区阶段不调用全图 `mindMap.render()`。
- `YM-TEXT-027`：编辑会话期间 GeometryRepair 不运行。
- `YM-TEXT-028`：双击打开事务拥有焦点，能抵抗思源延迟恢复 `RootWebArea`，不需要第三次点击；用户真实点击或输入后立即释放焦点租约。
- `YM-REL-001`：测试 Bundle、ZIP Bundle、解压 Bundle 和 runtime Bundle SHA-256 完全一致。
- `YM-REL-002`：dirty 工作树不能执行正式 release 或 runtime sync。

逐帧用例必须覆盖打开前一帧到稳定后至少 60 帧；关闭和 A→B 切换同样执行。测试不得只比较总宽、高、行数或 CSS 类存在。

发布级验收继续执行正式清单全部适用门禁，并在真实思源冷启动后记录当前版本、`sourceBuildId`、运行目录哈希和新 Trace。

## 11. 版本与回滚

该改动修改共享排版契约、vendored runtime 和发布链路，属于兼容的主要子系统重构，目标版本为 `v1.9.0`。

回滚单位是完整 `v1.9.0` 候选提交与其发布 ZIP。不得只回滚生成 Bundle 或只覆盖运行目录部分文件。用户导图数据不参与回滚和清理。
