# KMind 编辑事务与几何测量对照研究

> 日期：2026-07-29 22:03
> 文档类型：设计
> 参考实现：`D:\myDatabase\SiYuan\data\plugins\siyuan-kmind-zen` v0.34.0
> 对照范围：大纲/导图双表面编辑、软换行、撤销重做、节点宽度拖动、几何测量

## 结论

KMind Zen 的稳定性不是来自某个单独的 CSS 或拖动补丁，而是来自三层分工：

1. 文档模型保存结构化富文本，软换行使用独立 `hardBreak` 节点，不把 `<br>` 当普通字符串反复转义。
2. 输入、粘贴、撤销和重做先进入统一事务，再投影到导图与大纲；两个表面不分别维护历史。
3. 几何变化通过 `ResizeObserver`、`requestAnimationFrame` 和相等性判断形成受控反馈环；指针移动只更新实时几何，完成拖动后才提交持久事务。

YeMind 当前“基础编辑事务与剪贴板重构”的方向与此一致。后续应继续收敛现有分层，不能再为导图、大纲、粘贴、折叠分别增加字符串补丁。

## 证据

参考插件只提供打包后的 `index.js`，没有源码和 source map，因此本次只采用可验证的运行时代码证据，不推测私有模块名称。

| 运行时代码特征 | 出现次数 | 可确认的设计意图 |
|---|---:|---|
| `hardBreak` | 33 | 软换行是文档结构节点，不是拼接后的 HTML 文本 |
| `beforeinput` | 14 | 在浏览器实际修改 DOM 前识别编辑意图 |
| `ProseMirror` | 68 | 使用结构化富文本编辑器及其事务/选区模型 |
| `addToHistory` | 5 | 明确控制哪些操作进入统一历史 |
| `ResizeObserver` | 18 | 监听真实布局尺寸变化 |
| `requestAnimationFrame` | 99 | 把布局读取和写入合并到帧边界 |
| `MutationObserver` | 16 | 对宿主和浮层结构变化做失效通知 |

同时，KMind 的命令表明确区分：

- `Set node content width`、`Set node content width mode`、`Reset node content width`；
- `Undo`、`Redo`；
- `Add sibling`、`Add child`、`Delete selection`；
- `Flush cached docs to store`、`Reload cached docs from store`。

这说明节点宽度、文档编辑、结构编辑和存储刷新是不同事务，而不是一次 DOM 修改同时承担所有职责。

## YeMind 采用方案

### 1. 正文只保留一个权威表示

- 节点正文以规范化 HTML/纯文本语义为权威数据。
- `<br>`、换行和块级内容只在解析边界转换一次。
- 禁止在加载、折叠、展开、换主题、重开时把已经规范化的 HTML 再编码成 `&lt;br&gt;`。
- `structuredOutlineDocument`、画布富文本和持久化使用同一边界清洗函数。

### 2. 双表面共享事务

- 画布和大纲只是同一节点模型的两个投影。
- 输入、粘贴、Delete/Backspace、Shift+Enter、Undo/Redo 都携带稳定 UID 和事务来源。
- 文本事务只更新受影响节点；结构事务才允许替换树。
- Undo/Redo 完成后强制把模型重新投影到两个表面，不复用过期 DOM Range。

### 3. 编辑几何原子提交

- 活动编辑器、静态文本层、节点外框和选择框属于一个渲染事务。
- 输入或粘贴时，先提交正文，再在同一生命周期刷新编辑器测量和 SVG 几何。
- 同一 UID 编辑期间只保留一个可见文本层，避免“上层编辑器 + 下层静态文本”闪烁。
- 退出编辑前 flush 当前事务，不能依赖 blur 后偶然重绘。

### 4. 宽度拖动分为预览和提交

- `pointermove` 只更新实时 `customTextWidth` 和布局预览。
- 实时重排前把宽度镜像到当前节点实例，避免全树重绘读回旧值。
- `pointerup` 只产生一个可撤销的最终宽度事务。
- 拖动期间禁止重复创建节点、重复布局历史或执行适配视图。

### 5. 观察器必须有回路保护

- `ResizeObserver` 只发出“几何失效”信号。
- 实际测量合并到单个 `requestAnimationFrame`。
- 写入前比较宽、高、行高和文本布局；差异小于阈值时不再写入。
- 所有观察器、动画帧和全局指针监听在编辑结束或编辑器销毁时清理。

## 不采用的做法

- 不从 KMind 打包代码直接复制压缩实现。
- 不把 ProseMirror 整体引入 YeMind 作为本轮修复；当前 Quill 与结构化大纲可以实现同样的事务边界。
- 不用延时、重复 `reRender()` 或高优先级 CSS 掩盖竞态。
- 不把 `width`、`customTextWidth`、DOM `clientWidth` 和 SVG 外框宽度同时当作权威值。
- 不在折叠、主题切换或重开时重新解析并覆盖节点正文。

## 对应回归

- 输入、粘贴和清空后，编辑器、节点外框和选择框在一帧内一致。
- 末尾 `\n` 粘贴不产生额外空白行。
- Shift+Enter 生成一个稳定软换行；折叠/展开、保存/重开后不变化。
- 大纲删除后，Undo/Redo 同时更新大纲与导图。
- 节点宽度拖动过程无文字跳到左上角、节点消失或旧宽度回弹。
- 一次宽度拖动只产生一个历史事务。

## 本轮实机结果

2026-07-29 在思源 v3.7.3 冷启动后验证：

- 旧复杂导图的多行节点打开后仍保持多行。
- 节点宽度从 281px 缩到 167px 时，外框与文字实时换行，节点未消失；Undo 恢复到 281px。
- Shift+Enter、Undo、Redo 在导图与大纲同时生效。
- 粘贴 `Alpha\nBeta\n` 后没有尾部空白行，节点外框立即适配两行；提交后大纲同步，Undo 恢复原文。
- 折叠再展开父分支后，多行正文没有变成单行或出现 `&lt;br&gt;`。
- 大纲从右向左快速框选并越过彩虹线后，Delete 正常删除真实选区；Undo 同时恢复两个表面。
